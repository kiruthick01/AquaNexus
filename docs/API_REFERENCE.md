# API Reference

FastAPI serves the live, authoritative schema at `/docs` (Swagger) and
`/openapi.json`. This document covers what the schema cannot: which model to
call, what the numbers mean, and where they should not be trusted.

**Base URL** `http://localhost:8000` · **Version** 0.1.0 · no authentication

---

## Read this first: two models, different provenance

| | `dissolved_oxygen` | `hsi` |
|---|---|---|
| labels | **real measurements** (公共用水域 monitoring record) | **generated by this repository** |
| unit | mg/L | index, 0–1 |
| model | Ridge regression | XGBoost |
| trained on | 138 observations, 4 stations | 4,717 rows (53 sections × observations) |
| cross-validated R² | **0.44** (whole stations held out) | 0.99 — *function recovery, not skill* |

`hsi` will always look like the better model. It is not: its labels are computed
by `aquanexus.data.synthetic`, so a high score measures how well a regressor
recovers a formula this project wrote. `labels` is `"SYNTHETIC"` in every
response that carries it, and the caveats say so.

Every prediction response includes `caveats`. They are not boilerplate — the
dissolved-oxygen model is biased by about −2 mg/L below ~2 m³/s, which is where
oxygen stress actually matters. Show them to whoever sees the number.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | Service description |
| GET | `/health` | Liveness and whether models loaded |
| GET | `/models` | Provenance, metrics and caveats per model |
| POST | `/predict` | One state → one prediction |
| POST | `/batch_predict` | Up to 1,000 states |
| POST | `/explain` | SHAP contributions for one state |
| POST | `/scenario_run` | Compare a modified state against a baseline |

### The environmental state

Every prediction endpoint takes the same object. All fields are optional —
supply what you have; the API derives what it can (DO saturation from
temperature, Froude number from depth and velocity, cyclic terms from month) and
leaves the rest missing rather than refusing the request.

| Field | Unit | Accepted range |
|---|---|---|
| `water_temp` | °C | −2 … 45 |
| `air_temp` | °C | −30 … 45 |
| `dissolved_oxygen` | mg/L | 0 … 25 |
| `discharge` | m³/s | 0 … 5000 |
| `depth` | m | 0 … 30 |
| `velocity` | m/s | 0 … 10 |
| `suspended_solids` | mg/L | 0 … 5000 |
| `ph` | — | 3 … 11 |
| `nitrogen_total` | mg/L | 0 … 50 |
| `phosphorus_total` | mg/L | 0 … 10 |
| `month` | 1–12 | seasonal terms |

Those bounds are **physical limits, not the training range**. A value inside the
bounds but outside what the model has seen is answered and flagged in
`out_of_range` — see below.

### `GET /health`

```json
{
  "status": "ok",
  "version": "0.1.0",
  "river": "Ayase (綾瀬川)",
  "models_loaded": ["dissolved_oxygen", "hsi"],
  "detail": null
}
```

`status` is `"degraded"` when no model could be loaded, with the reason in
`detail` — the process stays up and explains itself rather than refusing to
boot. Returns 200 either way, so a liveness probe passes while a readiness check
on `models_loaded` fails.

### `GET /models`

Per model: `target`, `unit`, `model_type`, `labels`, `n_train`, `features`,
`metrics`, `caveats`. Returns **503** when nothing is loaded.

### `POST /predict`

```bash
curl -X POST http://localhost:8000/predict \
  -H 'Content-Type: application/json' \
  -d '{"target": "dissolved_oxygen",
       "state": {"water_temp": 24.5, "discharge": 12.0, "depth": 1.8,
                 "velocity": 0.45, "month": 7}}'
```

```json
{
  "target": "dissolved_oxygen",
  "prediction": 4.95,
  "unit": "mg/L",
  "interpretation": "4.95 mg/L - hypoxic stress likely",
  "labels": "observed",
  "uncertainty": null,
  "out_of_range": [],
  "contributions": null,
  "caveats": ["Labels are real measurements from the 公共用水域 monitoring record.", "..."]
}
```

`uncertainty` is the spread across a tree ensemble, and **null for the Ridge
model** — which cannot express one. A fabricated constant would be worse than a
null.

Set `"explain": true` to include `contributions`. The first such call per model
takes a couple of seconds while the SHAP explainer is built; subsequent ones are
~200 ms. A failure to explain returns the prediction with `contributions: null`
rather than an error.

**Out-of-range inputs are answered, not refused:**

```json
"out_of_range": [
  {"feature": "discharge", "value": 900.0, "training_min": 0.17, "training_max": 73.71}
]
```

The caller is told and decides. In the example above the prediction clips to
0.00 mg/L — a discharge 12× the largest ever observed is extrapolation, and the
response says so.

### `POST /batch_predict`

`{"target": ..., "states": [...]}`, 1–1000 states. Rows are predicted
individually, so one bad row returns `NaN` in its position instead of voiding
the batch. `out_of_range_count` reports how many rows carried a flag.

### `POST /explain`

Same request shape as `/predict`. Returns contributions that **sum to
`prediction - baseline`**, largest first, plus:

```json
"collinear_pairs": [["water_temp", "do_saturation"], ["reach_velocity", "reach_top_width"], "..."]
```

Read those pairs before ranking anything. The hydraulic features are all derived
from discharge through the same HEC-RAS model, so SHAP divides credit between
them arbitrarily — ten pairs on this model correlate above 0.9. Their
contributions are one combined effect, not a league table.

SHAP compares a prediction against a **reference distribution**, which ships
beside each model as `<target>_background.csv`. If it is missing the endpoint
returns 503 rather than the zeros an explainer with no reference would produce.

### `POST /scenario_run`

```bash
curl -X POST http://localhost:8000/scenario_run \
  -H 'Content-Type: application/json' \
  -d '{"scenario_name": "drought", "target": "dissolved_oxygen",
       "baseline": {"water_temp": 24.5, "discharge": 12.0, "depth": 1.8,
                    "velocity": 0.45, "month": 7},
       "modifications": {"discharge": -0.6}}'
```

`modifications` are fractional (−0.6 = 60% less); `absolute_modifications` set
values directly and win where both name a field. Fractions below −1.0 are
rejected. Fields absent from the baseline cannot be modified (422).

**This is a model sensitivity, not a forecast.** Changing discharge carries the
hydraulics with it: depth, velocity and width are re-interpolated from the
HEC-RAS flow sweep at the new discharge, which is how the training rows were
built. The response lists what was re-derived under `derived`. The simulation
itself is not re-run — the sweep is a precomputed set of steady-flow profiles.

A caller who sets `depth` or `velocity` explicitly is taken at their word and
nothing is re-derived for them.

Below about 2 m³/s the result should not be believed regardless: the model is
biased about −2 mg/L in that band, and most of its low-flow evidence comes from
a single shallow upstream station. See `notebooks/05_model_validation.ipynb` §6.

## Status codes

| Code | Meaning |
|---|---|
| 200 | OK |
| 422 | Request rejected — empty state, out-of-schema value, unmodifiable field |
| 500 | Unhandled error, returned as JSON (`{"detail": "internal error", "path": ...}`) |
| 503 | Model or explainer unavailable; `detail` says which and why |

Every response carries `X-Response-Time-ms`. CORS is open to
`http://localhost:3000` and `http://localhost:5173` by default
(`CORS_ORIGINS` in `.env`).

## Performance

Measured on the development machine (Windows, Python 3.12), single worker:

| Operation | Time |
|---|---|
| Model loading at startup (both models) | ~60 ms |
| Warm prediction | ~3 ms |
| First explanation per model (builds the SHAP explainer) | ~2.4 s |
| Subsequent explanations | ~190 ms |

Latency is dominated by SHAP, not by the models. Batch prediction of 100 states
costs about the same as one.

## Running it

```bash
uvicorn aquanexus.api.app:app --reload          # local, from a checkout
docker compose up                               # container, data mounted from ./data
python scripts/verify_deployment.py --url http://localhost:8000
```

`verify_deployment.py` runs the smoke checks in this document against a live
service and exits non-zero on the first real failure — including a degraded
start, which is what happens if the container runs without the `./data` mount.
Models are build outputs, not source, so the image deliberately carries none.
